Theoretical Workflow

How the Detection Engine Works

The plagiarism detector follows a disciplined 6-stage computational pipeline combining lexical preprocessing, polynomial rolling hashes, and hash-map verification.

1

Clean & Tokenize Text

Raw strings are normalized by folding uppercase letters to lowercase, stripping disruptive punctuation, and preserving exact word boundaries and character offsets.

"The Transformer Model" → ["the", "transformer", "model"]
2

Generate Word Shingles

The token stream is segmented into overlapping word sequences of fixed size k (n-grams of words). Shingles advance word-by-word, capturing local phrase syntax.

k=3: [w0, w1, w2], [w1, w2, w3], [w2, w3, w4]...
3

Compute Rabin–Karp Fingerprints

Each shingle is assigned a compact numeric fingerprint using a polynomial rolling hash. Moving the window to the next shingle requires only an O(1) arithmetic shift.

H_{i+1} = ((H_i - w_{out} · b^{k-1}) · b + w_{in}) mod M
4

Index in Hash Map

All fingerprints from the source document are stored in a Hash Map (inverted index). Each hash key points to the shingle's position and original word tokens.

hashMap.set(fingerprint, [occurrenceDetails...])
5

Verify Against Original Text

When a query shingle produces a matching hash in the map, the detector performs an exact word-by-word comparison to eliminate false positives caused by hash collisions.

if (sourceWords === checkWords) → Verified Match!
6

Score & Reconstruct Highlights

The engine calculates the Containment Score and merges overlapping matched shingles into smooth, continuous highlight spans for synchronized side-by-side inspection.

Containment = (|S_check ∩ S_source| / |S_check|) × 100%

Why This Approach?

Combining Rabin–Karp rolling hashes with hash-map indexing provides key architectural advantages over naive string matching and global sequence alignment:

  • ✓
    High Computational Efficiency: Rather than spending O(k) operations hashing every consecutive word chunk, the rolling property achieves O(1) time per shift, completing scans in milliseconds.
  • ✓
    Detection of Rearranged Passages: Unlike rigid diff tools or global sequence alignment algorithms that fail when paragraphs are transposed, shingles are indexed position-independently in the hash table.
  • ✓
    Extensible to Multi-Document Corpora: The hash map acts as an inverted index. Multiple reference textbooks or entire student cohorts can be indexed into the same map without slowing query time.
  • ✓
    Deterministic & Explainable: Unlike black-box neural similarity scores, rolling hash matches provide exact word offsets and cryptographic proofs for human audit.

Limitations & Shingle Trade-offs

While exceptionally fast for verbatim and near-exact copying, word-shingling has inherent linguistic constraints that users must understand:

  • !
    Blind to Paraphrasing & Synonyms: If a student systematically replaces words with synonyms or rephrases active voice into passive voice, exact word shingles will fail to match.
  • !
    Sensitivity to Word Order Changes: Swapping two words inside a 5-word shingle alters both shingles spanning those words.
Shingle Size (k) Sensitivity Trade-off Impact
k = 2 – 3 Very High Matches common conversational idioms ("in order to", "on the other hand"), producing frequent false positives.

Complexity Analysis & System Architecture

Understanding why Rabin–Karp with Hash Maps scales to large text collections.

Index Construction

O(n)

Tokenizing n words takes O(n). Computing the first shingle hash takes O(k). Each subsequent (n - k) shingle is computed via the rolling hash formula in O(1) arithmetic operations and inserted into the hash map in O(1) average time.

Document Querying

O(m)

Scanning a suspect text of m words similarly rolls the hash window in O(1) time per shingle. Hash map lookup takes O(1) average time, making query scanning strictly linear in the length of the checked text.

Total Expected Time

O(n + m)

The overall average execution time is approximately linear O(n + m). In the worst case of catastrophic hash collisions, collision verification can degrade to O(n · m), but choosing a large prime modulus (M = 261 - 1) reduces this risk to practically zero.

Memory Space

O(n)

Storing the source text's tokens, shingle metadata, and hash map bucket pointers requires memory directly proportional to the source document size n.
